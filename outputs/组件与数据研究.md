# 金铲铲 DataJ Companion：组件、数据与许可证研究

核查日期：2026-09-25。来源仅采用项目仓库、官方文档与 DataJ 实际页面。未安装运行候选程序、未对游戏画面做 OCR 测试。下文区分已查事实、工程建议和待验证事项，不以 star 数或作者宣传代替性能证据。

完整游戏助手的源码审计、固定 commit 链接和维护状态见 [开源助手源码审计](project-audit.md)。

后续 P0 已定位当前 DataJ 入口，并验证四类核心查询的典型结果；本机目标也已确认为 Windows 10 x64、MuMu 全屏。下文保留初始调查记录，取数与环境的最新状态以 [P0 验证记录](P0验证记录.md) 和 [MVP 技术设计](MVP技术设计.md) 为准。

## 1. 复用结论

**最值得研究的完整助手是 JinChanChanTool；最值得实际复用的是独立的 OCR、截图和 UI 库。** 新建 Companion 的理由来自需求差异：现有助手包含自动操作、TFT 数据或攻略采集；本项目要的是金铲铲的 DataJ 统计口径和两种显示窗口。移植整仓并不能免除数据适配、识别样本和许可证工作。

不沿用前文“70% 可复用”“回合识别很容易”“一晚上完成”等没有样本和工程验证的估算。旧对话中未提供明确仓库身份的“AI Screen Assistant”“TFT Overlay 图标识别项目”不作为已验证候选。

## 2. 通用开源组件矩阵

| 组件 | 一手来源能确认什么 | 复用建议 | 许可与限制 |
|---|---|---|---|
| [RapidOCR](https://github.com/RapidAI/RapidOCR) | 多推理后端 OCR，官方使用文档推荐先试 ONNX Runtime CPU | **首选 OCR 封装**；只读取回合和卡片名称区域 | Apache-2.0；模型来源单独记录，不能用库许可涵盖所有模型/字库 |
| [PaddleOCR](https://github.com/PaddlePaddle/PaddleOCR) | OCR 工具链和模型上游，Apache-2.0 | 作为模型依据/备选引擎；RapidOCR 难例不达标时再对照 | 核对实际权重和依赖；不以文档扫描指标推断游戏字体准确率 |
| [ONNX Runtime](https://github.com/microsoft/onnxruntime/blob/main/LICENSE) | MIT 授权的推理运行时 | 初版 CPU，避免先引入 GPU 部署矩阵 | 模型本身不随运行时 MIT 自动获得许可 |
| [python-mss](https://github.com/BoboTiG/python-mss) | 基于 ctypes 的多显示器截图；仓库说明 Python 3.10+ | **首选截图后端**，低频局部截取 | [MIT](https://github.com/BoboTiG/python-mss/blob/main/LICENSE.txt)；画面遮挡/最小化不在本版承诺内 |
| [DXcam](https://github.com/ra1nty/DXcam) | Windows 捕获，当前说明含 DXGI/WinRT 后端 | 截图兼容或性能出现实测问题时替换 | [MIT](https://github.com/ra1nty/DXcam/blob/main/LICENSE)；作者 FPS 数据不是本项目成绩 |
| [PyGetWindow](https://github.com/asweigart/PyGetWindow) | 窗口枚举、标题和位置等，README 当前仅实现 Windows | 窗口选择器参考；生产边界仍需客户区/DPI/进程身份校验 | [BSD 三条款文本](https://github.com/asweigart/PyGetWindow/blob/master/LICENSE.txt)；窗口标题不等于游戏画布 |
| [PySide6 / Qt for Python](https://doc.qt.io/qtforpython-6/) | Qt 官方 Python 绑定；[窗口标志](https://doc.qt.io/qt-6/qt.html#WindowType-enum)提供置顶、输入穿透、不接受焦点等能力 | **首选 UI**：Widgets 浮层＋侧栏，WebEngine 显示原站 | LGPL/GPL/商业多许可；按实际模块选择许可，并检查第三方组件 |
| [Qt WebEngine](https://doc.qt.io/qt-6/qtwebengine-overview.html) | 基于 Chromium 的网页显示和脚本能力 | 侧栏承载原阵容页；需实测网站兼容、窄屏和复制行为 | [Qt 与 Chromium 各自许可](https://doc.qt.io/qtforpython-6/overviews/qtwebengine-licensing.html)，不能只带一个顶层 LICENSE |
| [OpenCV](https://github.com/opencv/opencv/blob/4.x/LICENSE) | 4.x 许可为 Apache-2.0 | 图像裁剪、预处理和必要的布局/图标匹配 | 实际 Python wheel 的第三方组件需随包审计；非必需组件不装 |
| [HTTPX](https://github.com/encode/httpx) | 同步/异步 HTTP，项目标识 BSD-3-Clause | 有已核实数据接口时作为客户端 | 该许可不授予访问目标站点或再分发目标数据的权利 |
| [Playwright Python](https://github.com/microsoft/playwright-python) | 浏览器自动化与测试库 | **开发期优先用于 DataJ 行为验证和回归**；运行期是否携带待 P0 决策 | [Apache-2.0](https://github.com/microsoft/playwright-python/blob/main/LICENSE)；浏览器二进制和站点权利另计 |
| [Electron](https://www.electronjs.org/docs/latest/api/browser-window) | 浏览器桌面窗口 API | 备选，当前不引入 JS/Python 双栈 | [MIT](https://github.com/electron/electron/blob/main/LICENSE)，发行物还有 Chromium 等第三方条款 |

选择 Python 3.12 x64 是工程建议。RapidOCR 当前 [pyproject](https://github.com/RapidAI/RapidOCR/blob/main/python/pyproject.toml) 声明 Python `>=3.8,<4`；mss README 声明 3.10+，两者不构成与某个 PySide6/ONNX Runtime 版本组合已通过测试的证据。Qt 安装要求以 [当前官方安装说明](https://doc.qt.io/qtforpython-6/gettingstarted.html) 和实际锁定 wheel 为准。第一轮只验证一套组合，记录版本、wheel 平台与模型哈希，不在设计阶段伪造可运行锁文件。

## 3. DataJ 现场核查记录

本轮在浏览器正常访问公开页面，没有登录、绕过限制、批量抓取或调用未经验证的私有 API。

| 页面 / 操作 | 实际观察 | 能支持的结论与边界 |
|---|---|---|
| [全局强化统计](https://www.dataj.cc/hex) | 名称搜索、区分阶段、阶段/品质控件，表内均排/前四/登顶列 | 可作为全局强化查询基准；未验证所有筛选组合和分页 |
| [数据检索器](https://www.dataj.cc/explorer) | 英雄/羁绊/装备/强化条件入口、添加分组、阵容等结果标签、最小样本 | 支持所需手动查询入口；本轮没有完成单条件结果与多条件逻辑实测 |
| [阵容排行](https://www.dataj.cc/comp) → [地狱火95](https://www.dataj.cc/comp/112) | 有前期/人口变体、站位与强化推荐，下面有英雄/装备/强化/趋势标签 | 原阵容页适合作为跟随阅读内容；Qt 内嵌尚未测试 |
| 阵容页 → 强化符文 → 勾选区分阶段 | 勾选前厨神阿福：阶段合并，均排 3.55、17,059 对局；勾选后出现 2-1：3.52、11,193 对局，3-2：3.65、3,454 对局 | 页面确实有阵容内阶段化统计，不能拿合并行冒充当前阶段行 |
| 阵容页 → 英雄默认选中阿木木 → 装备 | 石像鬼石板甲一行显示 22,673 对局、均排 3.42；存在最小样本与装备类型控件 | 有“阵容内英雄装备”查询形态；特殊装备筛选、星级条件的具体语义尚未验证 |

上述数字仅是本轮页面快照，用于证明字段与交互，不用于推荐海克斯或装备。页面当时显示 S18 / 18.2a；不是用外部游戏公告核验后的当前赛季承诺。页面总局数也不能充当某一统计行样本。

DataJ 公开页面标示为非官方数据网站。此次访问与定向检索未取得公开开发者 API、服务级别承诺或第三方再展示授权文件。**网站可访问、页面有数据、某开源项目写了爬虫，均不是数据使用许可的替代证据。** 本轮不据此下“合法/非法”定论，下一阶段须记录站方实际使用条件。

## 4. 许可证风险与具体处理

这是工程依赖筛查，公开发布前应对锁定版本和发行物再核对；不是针对所有使用方式的法律结论。

| 类别 | 当前风险 | 本项目处理 |
|---|---|---|
| MIT / BSD / Apache 组件 | 较低但有保留声明、许可证、适用 NOTICE 等义务 | 维护组件清单；发行包附相应材料，保留修改/来源记录 |
| PySide6 / Qt / WebEngine | 中等：多许可、模块与 Chromium 依赖、LGPL 发行义务 | 优先保留独立 DLL/模块的部署方式；核对替换/重链接、声明与相应源码提供要求；不能把“动态链接”当全部合规条件 |
| GPL 助手源码 | 对希望保留未来闭源发布选择的项目较高；不是“不能商业使用” | 不直接复制 GPL 模块；若未来选择 GPL 派生路线，按实际许可履行相应源代码和分发义务 |
| 无 LICENSE 或非商业限制的公开仓库 | 高：不能按宽松开源许可推定可复制/修改/分发 | jcc-assistant 只用于概念参考；需要复制时先取得清晰授权 |
| OCR 权重、图标、游戏名称/素材 | 与代码独立 | 模型记录下载源、哈希、许可；游戏图标不因为在 GitHub 出现就重新按 MIT 分发 |
| DataJ 统计、攻略与网页 | 与所有代码许可证独立 | 原站保留来源；自动读取、缓存、嵌入、公开再展示分别核实使用条件 |

依据：[Qt 开源义务说明](https://www.qt.io/development/open-source-lgpl-obligations)、[Qt 模块许可说明](https://doc.qt.io/qt-6/licensing.html)、[GitHub 对无许可证仓库的说明](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/licensing-a-repository)、[RapidOCR 模型权利与来源清单](https://github.com/RapidAI/RapidOCR/blob/main/python/MODEL_LICENSES.md)。RapidOCR 的当前清单区分工程代码与模型，并限定所覆盖的模型；新增权重仍须单独查源。

前文建议 PyQt5 需要修正：[Riverbank 官方](https://www.riverbankcomputing.com/software/pyqt/intro)明确 PyQt 是 GPLv3/商业双许可，不提供 LGPL。改用 PySide6 是重新实现 UI 的技术选择，不会消除此前复制的 GPL 源码的义务。

本项目只读截图、没有自动操作是功能边界，不能因此宣称已获游戏方许可或“不会封号”。本轮未完成金铲铲现行规则适用性审查，也不拿海外 TFT 政策直接代替它。公开发布时将其作为单独事项处理。
