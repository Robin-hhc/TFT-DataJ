# 数据显示基线

这些是 S18 的公开 DataJ 响应，不包含玩家截图、账号或私人录像。

- `amumu-equipment.json`：2026-09-28 首次确认的英雄出装错例。旧助手首行是仅 3 局的光明版生命药水；网站 50 局门槛下首行为护卫纹章 3.15 / 920 局。完整的单件和三件套预期分别为 40 / 111 行。
- `matrix.json.gz`：两个版本（18.2a、18.2）、20 个基础检索条件、9 个海克斯、9 件装备、三套阵容及其英雄出装。清单在 `matrix`，真实响应在 `records`，参考答案在每条记录的 `expected`。

## 参考答案如何产生

参考级别为 **公开接口响应＋已核实的网站展示规则**，不是逐页网站 DOM 对账，也不验证网站上游统计计算。助手测试代码不能生成参考答案。

50 局门槛来自 [DataJ 阵容页面](https://www.dataj.cc/comp/112) 当时引用的[前端组件](https://www.dataj.cc/_next/static/chunks/0969vttc_sol9.js)。2026-09-28 保存的组件 SHA-256：`eb4f223bf890fddc3d01f212837b19bc6184be179b170cff27011f6ab0532535`。英雄单件和三件套先过滤样本，再按均排升序；三件套类别按“包含”筛选。检索器 50 局规则也保留在已有 `../explorer-dark-ritual.json` 错例中。

`tools/build_display_golden.py` 不导入应用模块，独立投影这些规则，显式生成新候选文件。审核后才能加入这里；采集器和测试均不会覆盖已有基线。并列项保留来源顺序，不声称网站具有额外的并列优先级。

海克斯按 ID、阶段索引及阶段标签取值；无阶段不退回总值。装备均排取直接装备聚合；阵容缺项时使用同条件检索器对应阵容，不能平均持有者结果。持有者按样本≥50、当前攻略英雄 ID 集合筛选。目录没有的装备类别不会猜测：保留在“全部”，不进入具体分类。

每条记录保存请求维度、时间、原始响应字节 `sha256`；`projected_sha256` 校验仓库内投影内容。完整原始字节及采集失败证据保留本地 `work/data-display-matrix/`。投影删除检索器中未使用的统计类别及大部分目录字段；不对原始字节哈希冒充可由投影重算的哈希。

当前海克斯小于 50 局保留均排并显示“少”；这是助手的明确显示规则。英雄出装和阵容排行榜会过滤小样本，装备候选均排只标“少”。

海克斯缺失状态区分识别与统计：未确定实体时显示“未识别”；已识别但统计表缺少唯一对应项时，全局显示“暂无全局统计”，阵容显示“本阵容暂无统计”。实体存在但缺少当前阶段显示“无该阶段数据”；零样本、非法均排或样本数显示“统计不可用”；不支持的阶段显示“阶段待确认”。这些状态均不能借用总均排或其他阶段数值。

2026-10-08 对冻结矩阵仅迁移缺项文案：114 个 `expected` 文本（全局 6 个、阵容 108 个）从“无数据/未识别”改为对应统计缺失状态。165 条响应的请求、数据、来源哈希及矩阵覆盖均未改变；数值答案和“无该阶段数据”文本也未改变。该旧矩阵继续只验证原始海克斯统计表；新增的精确检索补查由独立专项接口与截图回归覆盖，不向此基线混入新网络响应。

## 覆盖及限制

固定种子 `180928`。包含普通装备、转职、强化、英雄、羁绊各 4 条；其中英雄目录包含冷门实体、羁绊包含同一羁绊不同档位。实际空结果仍作为空结果验证，不能替换为全局列表。统计 ID 与目录 ID 可能不同，头像回退只使用一致的图片地址，统计不按名字合并。

每次运行输出每个案例的状态。缺失资料、未执行、来源失败均不算通过；CI 与 EXE 校验拒绝缺少必选请求的基线。真实截图/OCR、游戏帧率、原站攻略及其他电脑兼容性是另外的验收项。
