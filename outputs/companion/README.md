# 金铲铲 DataJ Companion · 本机试用版

可双击本目录 `start-companion.cmd` 启动。已在当前工作区配置运行环境，不需要重新安装。自动识别默认开启，收起面板并保持 MuMu 在前台后工作；截图在内存处理，不默认保存游戏画面。应用不会替你操作游戏。

## 可用功能

- 海克斯：选择阶段和三个明确的海克斯 ID，显示全局均排；固定阵容后增加该阵容的阶段均排。相同名字保留品质、ID和描述供确认，不自动任选。
- 装备选择：自动查找底部3～5项选择，识别普通成装、神器/奥恩和光明目录实体；显示全局均排、固定阵容均排及最多两位对应范围的持有者。忽略散件；无法确认的选项不猜ID。成装、神器已通过本赛季录像回放，光明仍缺真实选择图片验收。
- 截图识别：读取本地截图，或者绑定前台 MuMu 后识别。目录和统计限定 S18，请求版本默认 18.2a，可手动修改为来源支持的 S18 版本。
- 选阵容：首页展示阵容卡片、核心英雄、均排和样本，支持搜索、排序、收藏。上方检索器每次只使用一个装备、转职、海克斯、英雄或羁绊条件；清除后回到全部阵容。与 DataJ 默认门槛一致，只展示当前条件下样本≥50局的阵容，再按所选指标排序；没有满足门槛的结果时显示空列表。
- 阵容攻略：点击卡片即固定并打开攻略，顶部复制主阵容码；“换阵容”返回列表。网页浏览不会改变本局目标，点击已固定卡片会返回对应攻略。变体码请在原站复制。
- 出装：固定阵容后点击英雄头像即查，可切单件/三件套，筛选神器、光明等类型。三件套按包含所选类型筛选。
- 界面调整：「识别 / 设置 → 手动查询与高级设置」可选窗口尺寸、字体大小或回到左上角。标题栏、边缘和小标记可拖动，退出时保存位置和尺寸。

## MuMu 全屏

1. 打开助手，等待后台准备完成；需要阵容内数据时先点击一套阵容，然后收起面板。唯一 MuMu 会自动连接，多个模拟器才需要手动选择。
2. 默认自动检查：每 3 秒读取顶部回合，2-1、3-2、4-2 各开启最多 60 秒海克斯检查；每 2 秒读取底部45%区域，轻量判断装备选择。共用截图和识别队列，平时不持续识别整屏文字。
3. 海克斯或装备选项出现后，可按鼠标后退侧键立即补查，`Ctrl+Alt+F10` 同样可用。装备均排先显示，持有者稍后补齐；不需要切换识别模式。
4. 左上角「阵容助手 · 展开」或 `Ctrl+Alt+F9` 展开/收起；关闭窗口或 `Ctrl+Alt+F12` 退出。识别页可暂停自动检测，暂停后保留侧键查询。

手动海克斯查询最多保留 30 秒有效性检查；候选变化、失焦或超时撤下结果。装备选择显示期间每 0.5 秒局部检查变化，稳定文字复用结果，结束选择后清除。面板的“读取截图”当前仅用于海克斯离线回放；装备回放入口见下文。

手动温热流程在内存原图和冻结统计下约 0.70 秒；不包含真实屏幕截取、网络和冷启动，不能作为实战延迟承诺。快速路径当前限定已验证的 16:9 布局。见 [设计及验证](../手动触发与阶段浮窗.md)。

无论浮层是否显示，都不会点击游戏或注入按键。采集不主动隐藏浮层：海克斯浮层位于卡片下部档位徽标处；装备浮层在对应选项及“选择一件”标题上方，保留原有名称与按钮。装备浮层设置为鼠标穿透、不激活窗口，尚待MuMu装备画面验证真实点击。

装备数据使用当前选中的版本。未定阵仅显示全局；定阵后增加阵容均排，并将持有者限定为攻略名单内的英雄ID。持有者按均排升序，样本不足50局不展示；装备均排不足50局标“少”。阵容表缺项时单装备查询检索器，找不到则显示“暂无数据”，不平均英雄数值来替代。

## 状态与失败

新的一局会清空阵容、阶段、候选和检索条件。切换版本、目标阵容、候选或窗口状态时旧响应不能覆盖新状态。面板打开或游戏失焦时撤下浮层。

缓存保存在工作区 `work/companion/cache.sqlite`，目录缓存一小时、统计十五分钟，按请求版本及全部参数隔离。最多同时保留八个任务；数据请求串行、间隔至少一秒，失败后短暂冷却，不循环重试、不用过期缓存冒充当前数据。缓存策略是本机试用配置，不代表 DataJ 对长期自动访问的许可。

原站嵌入页只允许 DataJ HTTPS 主页面导航，不暴露本地桥接；文件选择、下载与页面权限默认拒绝。嵌入页自己的赛季/版本由原站控制，请核对与上方查询版本一致。

## 已知限制

- 已有 S18 实战录像 1 局、3 次选择事件、7 组候选快照，详见 [回放报告](../S18实战回放验证.md)。未达到原规划的 100 次选择事件、10 局和独立准确率门槛。
- 当前小模型对罗马数字等级不可靠。多视图未修复此前31个错例，保留拒识；大模型比较另见执行报告。
- 罗马数字笔画补偿只预填待确认建议，自动查询不会使用该建议 ID；需要手动确认后查询。
- 自动选择页判定沿用少量布局样本，无法保证覆盖当前全部卡面。画面变化检测较保守，动画可能导致结果撤下或无法稳定显示。
- 没有自动检测新局或游戏补丁；需要应用内“新的一局”和确认统计版本。目录元数据的 S19/18.18.1 与页面 S18 命名冲突未澄清。
- 完整点击穿透、刷新总延迟、游戏帧率影响、原站所有复制/筛选交互尚未验收。
- 装备：开发集7张原生720P正例33个选项确认32项、1项拒识，无错误ID；这不是独立准确率。尚缺光明选择、MuMu 16:9高清正例及游戏帧率对照。本轮未检测到MuMu游戏窗口，不能将录像回放当作实战验收。见 [装备接入与验证](../装备选择接入与验证-20260928.md)。

## 环境与交付边界

跨电脑使用 [Windows便携包](../../packaging/README.md)，完整解压后运行 `TFT-DataJ.exe`；依赖、网页引擎及OCR模型随包携带。EXE的日志和缓存位于 `%LOCALAPPDATA%\TFT-DataJ`。

本目录同时保留源码启动方式：保留 `outputs/companion`、相邻 `outputs/mumu-p0-probe` 和 `work/p0-runtime` 的相对位置；源码运行仍依赖原Python基础安装，不要把虚拟环境当便携版复制。源码日志在 `work/companion/run-*.log`，新构建的依赖锁定见 `packaging/requirements-runtime.txt`。

测试入口：`python -m unittest discover -s outputs/companion -p "test_*.py"`；`python outputs/companion/integration_check.py` 使用冻结响应测试界面操作；`python outputs/companion/app.py --self-test` 仅检查控件与离线目录，不采集游戏或访问站点。

装备验证：`check_item_replay.py` 回放本地真实图片；`check_item_flow.py` 检查识别、双口径均排、持有者、过期响应和连续帧稳定性；`render_item_preview.py` 使用真实DataJ数据在录像原帧上渲染Qt浮层。运行这些脚本需本地 `work/item-choice-samples` 和 `work/item-choice-probe` 样本；不包含在源码提交中。

模型与软件分别适用其许可证，本项目源码发布许可证未选择。便携包附带第三方声明、安装依赖的许可文本、Qt许可证与来源参考、模型归属及哈希；本轮产物用于跨电脑运行验证。原调研见 [组件与数据研究](../组件与数据研究.md)；正式对外发布前仍需补齐Qt/Chromium对应版本完整第三方材料及分发记录。

### 鼠标侧键查询（2026-09-27）

默认按鼠标的后退侧键查均排（通常为靠近手腕的侧键）。首页可改成前进侧键或关闭，设置会保存；Ctrl+Alt+F10 仍可备用。只在目标 MuMu 游戏处于前台时触发，松开按键查询一次，忙碌和短时间连按不重复排队。侧键原有操作不会被拦截；如果鼠标驱动把侧键改成了键盘宏，需要恢复为标准后退/前进侧键。

此次通过输入过滤、前台校验、去重和原有流程的离线测试，未用真实鼠标及游戏验收。助手未自动启动。
