# Companion 本机试用版实施与验证

日期：2026-09-26。根据用户“列出 task 后自主持续执行”的授权，已将原 P0 原语接成实际桌面应用，未自动操作游戏，也未要求用户开局配合。

## 已实现

状态与数据分离，截图/OCR/网络使用独立有界工作队列；固定阵容采用独立请求版本，避免收起面板误丢弃详情。候选变化、输入修改、几何或前台变化使旧显示失效。识别不支持的回合（如 3-1）直接拒绝，不沿用旧下拉阶段。

海克斯手动/文件识别查询、MuMu 前台采集和三卡浮层已接入。单条件检索覆盖海克斯、装备、英雄、羁绊档位；阵容详情需明确固定；主阵容码复制与变体范围分开；出装支持英雄 ID、单件/三件套及来源类型筛选。

DataJ 适配器保存请求上下文与获取时间，SQLite 按完整请求键隔离。目录一小时、统计十五分钟缓存；网络串行且至少间隔一秒；失败冷却六十秒，过期数据不作为当前值返回。最多八个待处理/运行任务，防止持续积压。来源身份校验覆盖阵容详情、阵容海克斯与英雄装备。

[Qt 页面接口](https://doc.qt.io/qtforpython-6.8/PySide6/QtWebEngineCore/QWebEnginePage.html) 和 [Profile 文档](https://doc.qt.io/qtforpython-6.8/PySide6/QtWebEngineCore/QWebEngineProfile.html) 用于实现独立临时网页上下文。没有向远程页提供 WebChannel 本地桥；拒绝文件选择、下载和页面权限申请，仅允许 DataJ HTTPS 页面导航。

## 等级识别模型比较

旧小模型三视图对31个已知合成错例，修复0、错误唯一ID为0、拒绝31。为了验证是否模型容量不足，另外从 RapidOCR 3.9.2 模型登记地址取得 [PP-OCRv5 server_rec ONNX](https://www.modelscope.cn/models/RapidAI/RapidOCR/resolve/v3.9.2/onnx/PP-OCRv5/rec/ch_PP-OCRv5_rec_server.onnx)。实测文件84,577,022字节，SHA256为 `e09385400eaaaef34ceff54aeb7c4f0f1fe014c27fa8b9905d4709b65746562a`。

对相同31个合成错例，大模型三视图只修复2个，拒绝29个，错误唯一ID为0；整批约107.84秒，不含模型构造。没有把2/31解释为实战准确率，也没有将它接入实时应用。结果在本机 work/companion/suffix-server-recheck.json。

[上游模型卡](https://huggingface.co/PaddlePaddle/PP-OCRv5_server_rec) 标注 Apache-2.0；该转换模型与默认v6模型的归属材料分别记录。未将此比较模型加入应用默认依赖或外部分发包。

## 保留的验收缺口
