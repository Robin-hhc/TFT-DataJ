## 已完成的链路

公开截图 → 本地 CPU OCR → 判断强化选择页 → 提取回合与三个卡名 → DataJ 词典精确匹配 → 在明确指定的历史快照中查阶段均排。

已实现为 [P0 验证工具](mumu-p0-probe/README.md) 的离线模块。结构化结果见 [OCR 验证结果](OCR验证结果.json)。这套程序目前只做开发验证，尚未接入游戏自动浮层。

## 样本与逐项结果

先人工看图记录回合与名称，再运行 OCR。标注不输入 OCR 或卡名提取逻辑，程序最后才用标注评分；规则在这些图片上开发，因此它们仍是开发集，不是独立测试集。截图赛季没有全部独立确认，不能因为名称相同就认定属于当前赛季。

| 样本来源 | 原始尺寸 | 人工标注回合 | 提取回合 | 卡名逐项对照 | 全图 OCR 耗时 |
|---|---|---|---|---|---:|
| [普通强化，3楼猫](https://game.3loumao.org/54479032) | 972×727 | 2-1 | 2-1 | 减益传播、辅助宝库、治疗法球 II：3/3 一致 | 1513 ms |
| [英雄强化，九游](https://www.9game.cn/news/8618321.html) | 1316×760 | 2-1 | 2-1 | 吞噬灵魂、咒能高涨、无双挑战：3/3 一致 | 1541 ms |
| [举重比赛等，抖音图片](https://www.douyin.com/shipin/7592448868885874715) | 950×540 | 2-1 | 2-1 | 举重比赛、猛将的荣耀、厨神阿福：3/3 一致 | 1771 ms |
| [天选的青睐，代练通](https://www.dailiantong.com/news/content_170340.html) | 2400×1080 | 3-2 | 3-2 | 天选的青睐一致；另两项把 I 读为 1：1/3 一致 | 2137 ms |

本轮结果：**回合提取 4/4，卡名 10/12，整组三卡全对 3/4**。允许 Unicode 等价形式及空白规范化，例如“Ⅱ”与“II”；不把数字 1 自动替换成 I。抖音样本的原始顶部 OCR 是“急2-1”，其中图标被并入文字；提取器只在顶部限定位置提取唯一的回合格式，并保留原置信分数约 0.861，不把它冒充高置信原文。

两张本机采集的模式选择页/大厅作为负样本，均因不存在强化选择标题而返回 unknown，没有误生成三个候选。数量只有 2，不足以代表所有负场景。

### I / 1 的具体错误

- 人工：`源计划上行链路 I`；OCR：`源计划上行链路1`。
- 人工：`秘法帮派 I`；OCR：`秘法帮派1`。

错误文本的置信分数仍分别约 0.957、0.935，说明高 OCR 分数不能直接当作正确率。本版保留原文并标出等级疑义，不用编辑距离或全局字符替换强配 ID；这些历史名称在本次 DataJ 目录也未精确匹配。后续可用标题图像复识别和明确的赛季/品质约束缩小歧义，但还没有证明该方案有效。

## 局部识别比较

先使用全图 OCR 找到卡名框，再在同一张图上裁剪三个名称、关闭文字检测只做识别。最终一次回放耗时为 **48.85、49.54、48.0、50.55 ms**，结果仍为 10/12。

这些数字只包括三张名称裁剪及识别：不含初次全图定位、回合读取、选择页检测、截图、网络和渲染，也不是 p95。裁剪框来自同一张图的检测结果，所以只能支持“已定位区域的识别很快”这一结论，不能证明候选刷新后仍可直接复用同样宽度的文字框。产品需要卡片区域校准，避免更长名称被旧框截断。

## 环境与模型可追溯性

本地隔离 Python 3.12.14，RapidOCR 3.9.2、ONNX Runtime 1.22.1、OpenCV 4.14.0.94、NumPy 2.5.3。推理使用 CPU，intra-op=2、inter-op=1，关闭方向分类执行。模型来自已安装 RapidOCR wheel，自定义路径要求文件存在，不在运行时自动下载。最终回放的模型构造约 673 ms，未计入表中逐图 OCR 时间。

实际用到的检测/识别模型为 PP-OCRv6 small，初始化还加载随包的旧方向分类模型。三个模型的 SHA-256 均与 [RapidOCR 模型归属与许可清单](https://github.com/RapidAI/RapidOCR/blob/main/python/MODEL_LICENSES.md) 中记录一致，完整哈希在结果 JSON 中。依赖安装来源和哈希另存本机 `work/ocr-install-report.json`；复现版本见 [环境锁定记录](mumu-p0-probe/environment-lock.txt)。[RapidOCR 官方用法](https://github.com/RapidAI/RapidOCR#-usage) 是 API 依据，具体行为也核对了已安装 3.9.2 源码。

回放前会核对每张图片的 SHA-256、依赖版本、模型哈希和引擎参数；任一项变更即拒绝沿用旧基线，要求重新执行全图 OCR。

网页图片只保留在本地开发样本目录，本交付没有把它们制作成公开图片数据包；源码许可不会自动覆盖游戏截图、字体和站点素材。

12 个测试通过，覆盖窗口截图前提、等级字符区别、非选择页拒绝、重复名称歧义、阶段缺失不回退和阶段索引/标签冲突、图片变更及环境/模型/配置变更拒绝；依赖完整性检查通过。该数量是逻辑测试数量，不是图片识别测试集大小。

下一步优先扩充公开开发样本中的名称等级、低清图、缺失卡片、裁剪图和非选择界面，并引入独立保留样本。随后把可配置的卡片区域与本机截图连接，验证刷新失效和实时显示。**当前无须用户专门开局配合开发**；实战画面在后续真实环境验收时再补。

本次不把 10/12 写成线上准确率，不把 4 张静态图等同于 4 局独立测试，也不声称已实现自动选海克斯或完整 MVP。
