# 启动后首次识别崩溃修复（2026-09-27）

## 复现与范围

系统事件记录 pythonw.exe / python312.dll 的 0xc0000005 访问冲突，另一次复现为 0xc0000374 堆损坏。仅启动和普通场景截图可以正常运行，真实海克斯选择图进入 OCR 后可复现；不能把空启动日志解释为没有异常。

使用本地 2-1 原图，在隐藏 Qt 窗口中经过真实初始化和后台 OCR 路径复现，游戏关闭后也可测试。无须用户开局或截图。

对照结果：后台 QThreadPool 初始化 OCR 后首次识别崩溃；主线程初始化、仍在后台执行识别时，同一输入正常。该结果定位到本机运行环境中的初始化线程问题，尚未证明原生库内部的具体缺陷。

## 改动

- 在主线程初始化 OCR，后续推理保留单个后台工作线程。
- 初始化失败显示错误状态，避免无提示失败。
- 启动日志启用 faulthandler，记录原生崩溃栈。
- 增加 check_startup_ocr.py：冷启动后识别真实原图三次；隐藏界面、冻结统计，不操控游戏。

## 验证

- 三次独立 python 冷启动，共九次识别成功。
- pythonw 无控制台方式冷启动与三次识别成功。
- 真实 launch.py 使用 pythonw 启动并定时正常退出。
- 35 项单元测试通过，浮层防闪烁、旧排名清理检查通过。

这次验证针对启动与首次识别崩溃，不代表重新完成整局游戏性能验收。
