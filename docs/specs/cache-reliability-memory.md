# 缓存恢复、原图保留与交付一致性

日期：2026-10-21。用户批准与前两项反复故障一起实施；英雄头像必须保留，既有性能预算不得放宽。

## 范围与取舍

当前已使用 SQLite 按完整请求键保存响应。约 78 MiB 的数据库并不是同等大小的常驻内存；目录解码对象约 1.79 MiB，海克斯部分约 0.25 MiB。另建全站关系库、每次识别查库、预取所有统计均无已证明收益，本轮不做。保留按需请求和现有热数据，不通过减少头像、热缓存、刷新频率或新增 HTTP 重取来换内存。

头像常用集 64 张，原图均为 96×96，Qt 解码约 2.25 MiB。统一缩略图会改变 18px 显示像素和高 DPI 图标分辨率，因此拒绝。曾评估用 257 张/16 MiB 原图 LRU 替代整批清空，但第 258 张时旧实现只留一张、LRU 会多留 256 张，违反本轮相同场景内存不增长的条件；该候选已撤回，生产头像模块与开工逐字节一致。保留保真回归和未采纳设计的红绿证据，不宣称普通场景内存下降。

## 缓存合同

1. 继续使用现有 SQLite cache 表和请求身份，键包含 method、path、setId、统计版本、完整 query/body。目录仍只按 setId，不能伪造历史版本目录。
2. 域方法提供显式验证合同；新 HTTP 数据通过包络及域验证后才发布到数据库。合法空列表照常缓存。原先有效值不得被坏的 HTTP 200 覆盖。
3. 命中也采用同一域验证。既有坏 JSON 或域数据按完整 key + fetched + 原 body 精确删除，随后沿用现有调度向来源重取。失效不能删除并发写入的新好值，即使新旧 fetched 相同；队列边界重新查到好值时直接命中，不额外请求。保留原 SQLite 短连接与持久性，不增加跨请求验证缓存、拒绝指纹、观察连接或常驻目录副本。
4. 公共低层 request 保持包络合同；共享 Future 的加入者仍检查自身业务合同，不能把 required_comp 等消费条件塞进真实 HTTP body。
5. 所有普通、后台、batch 路径保持并发上限、取消和失败冷却；正常请求数不增加。域坏值保持原先 1 秒间隔，已建立的 60 秒冷却不得缩短。2026-10-21用户接受故障恢复开销后，补充有限自动恢复合同：同一固定阵容预热对象累计SourceError失败最多3轮（含首次），前两轮后各保留唯一、至少60秒且服从共享冷却的Timer；第三轮无Timer，普通start/prioritize及晚到Timer不能绕过。已成功内容保留，手动查询不被禁用，显式新任务有新预算。全局统计失败则对同一候选组保留失败状态，普通同画面不能无限OCR/统计重查；手动请求或真正改变候选/阶段/版本/新局仍可继续。没有新增轮询、HTTP或常驻线程。
6. catalog_snapshot() 只本地读取同 setId 已验证目录，允许过期并明确 stale。统计不使用过期数据。新坏响应被拒绝后，旧好目录自然留在原表，无第二份常驻副本或数据库。
   snapshot 的坏行及 shared Future 严格加入者的无效结果也按 key + fetched + 原 body 立即物理失效，保留并发新值。
7. 应用仍先确认网页版本；不改变既有“未确认最新版本不得查统计/捕获”的保护。目录请求失败后，才允许已验证本地目录兜底，并在界面标明；当前版本全局统计若缺失，重复身份维持待确认，绝不能用旧统计猜 ID。

共享失败的边界：若同一 HTTP body 的 owner 采用更严格合同且失败，该 Future 的加入者沿用来源失败语义，本次都失败，不发布坏缓存；保留现有可取消恢复。普通无阶段 explorer 与 exact 阶段通常不是同一 key。同 body 不同消费合同的恢复仍以保守失败为界，本轮不新增原始网络结果分发框架。

v2缓存实现已独立审阅。正式11组、每组200次恢复回放中，小坏值的必要校验/精确删除使P50比同候选正常cold多6.685至7.309ms；完整863,031字节、894行末项坏目录多13.561ms，P95多15.075ms。这没有通过原恢复+5/+10ms预算；**2026-10-21用户明确答复“增加几毫秒就加吧”，接受此故障恢复成本。原失败结果保留，不改写为达原预算。**两边各1次MockHTTP，不含真实网络、服务器及失败冷却等待，不是旧失败响应与新成功结果直接同比。正常路径预算不变。实际交付还需补齐本节第5项持续故障重试上限并重新验收。

减少持久提交的v3 logical-miss/拒绝指纹、短生命周期data_version观察连接，以及msgspec解析候选均保留在work试验，未纳入最终运行代码。TRUNCATE/PERSIST/WAL在保持FULL同步并计入全部close后更慢；msgspec虽可省约1.61ms解码，却增加约11.53ms首次import和1.07MiB private memory，整链试验仍未达标。均拒绝，不改变真实数据库journal/synchronous或增加依赖。保留原19方法及断言，并额外保留普通网络并发新好值、坏JSON来源失败后重启恢复两项业务保护；“只能一次提交”仅是未采纳设计的内部试验，从未注册为业务验收合同。

## 固定验收条件

- 先真实 DataJ + 临时 SQLite + MockTransport 复现坏响应、恢复、同库新实例，随后红绿修复；并发精确失效、不同查询范围、合法空值、共享/后台取消均验证。
- 真 Qt 消费者验证头像原像素、尺寸、DPI 和热命中，不允许缩略或移除。
- 保留旧 14 类数据故障保护；失效机制被前置拒写替代时，保留原测试并追加 coverage_change_note 和真正相关的绕过验证故障。
- 正确性基线绑定开工 380 文件快照及此前 995 测试报告；最终主树和干净交付树各跑完整私有门槛、数据故障注入。未审核的 15 个样本不算通过。
- 原 10 个固定 OCR 场景继续逐场要求 P50 增量 ≤5ms，P95 增量 ≤max(5%,10ms)，截图、OCR、正常 HTTP 次数不增加。不得因失败调宽预算。
- DB、头像和 Qt 单独固定同机 A/A 噪声与测量合同，串行负载、冻结源码后比较；报告解码字节和 RSS 的边界。无可测收益或造成性能损失的优化撤掉。

- 独立解压真 EXE、联网及固定原图回放、头像可读性、设置保留分别留证；源码测试不代表真实游戏 FPS、物理侧键或另一台电脑。
