# 普通成装英雄与紧凑装备浮层（2026-10-06）

## 问题与已核实证据

用户反馈普通装备选择没有显示英雄，装备排名框过大、过高。当前源码目录为 `E:\tft-helper`。

运行日志记录 23:08:33.951 的普通成装候选 ID：2027、2018、2020、2044、2016；该次 OCR 390ms。旧日志没有逐项英雄请求完成记录，无法据此证明这次未显示英雄的确切网络原因。独立只读抽查当前 18.3 的棘刺背心和冕卫接口均有英雄数据，原始响应保存在 `work/item-compact-20261006/18.3-equip-{2027,2018}-holders.json`。

以下问题已通过可控制的 HTTP 响应、实际控制器和 Qt 控件复现：

- 同一组已确认装备的英雄查询失败后，手动刷新直接返回，无法补查。
- 已固定阵容时，缺失装备的阵容补查排在全部英雄查询之前，拖迟首位英雄显示。
- 英雄统计使用基础形态 ID，而图鉴使用带星级 ID；同名不同形态的拉克丝等无法通过一致名称取得头像。

## 修改

手动侧键刷新只补查失败的查询，保留已经显示的排名和头像，不重新 OCR 同一组已确认名称；自动帧检查不产生额外网络重试。继续遵守共享数据源冷却时间，正在请求时不重复加入任务。阵容缺失补查之前优先读取装备英雄；阵容和全局范围、最低 50 局样本要求不变。新增 `item_query` 日志记录范围、装备 ID、状态、耗时和是否命中缓存。

头像使用已有形态解析器补齐基础 ID 到星级图鉴 ID 的映射，精确原始 ID 优先，不混合同名形态；最多缓存四份图鉴映射。统计 ID、英雄排序、均排和样本不变。独立回放检查使用冻结图鉴的明确星级 ID 作为图像预期，不调用生产解析器，不修改冻结统计基准。

装备浮层逻辑高度从 132 缩至 96，宽度上限从 250 缩至 200。实际 4K、DPI 192 素材上的物理框从 **500×264 缩至 400×192 px**，上边缘从 **1134 下移至 1218 px**，即宽缩 20%、高缩约 27%、下移 84px。保留两位英雄头像、名称、均排颜色和样本。实际定位与截图预览共用 `item_overlay_geometry()`；继续点击穿透、无焦点显示及幂等绘制。
