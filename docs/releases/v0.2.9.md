# v0.2.9 · 海克斯刷新后保持半秒检查

2026-10-09 · Windows 10/11 x64 便携测试版。

[下载便携包](https://github.com/Robin-hhc/TFT-DataJ/releases/tag/v0.2.9)，先退出旧助手，完整解压后运行 `TFT-DataJ.exe`；保留 `_internal`，无需安装 Python 或 OCR 环境。设置与缓存继续保存在 `%LOCALAPPDATA%\TFT-DataJ`。

## 改动

- 海克斯选择期间，刷新重读和等待后继确认帧均保持约 0.5 秒的检查间隔，不再退回 1 秒。
- 新组选项不再继承旧组的 1.5 秒 OCR 冷却；已失效识别的成功或失败回调，也不会重新延长当前组的冷却。
- 同组选项复用识别结果与统计缓存，不会每半秒重复 OCR 或请求排名。识别失败与画面无法确认时仍保留退避，后台截图和识别继续限制为单任务。
- 保留独立后继帧确认，连续刷新时只允许当前组选项发布，防止旧排名重新闪现。

## 验证

修复提交 `df235f526413626da86272ae2f874aeb67e045cb` 的完整源码回归 617 项通过，0 失败、0 错误、0 跳过；356 组冻结数据显示、已核对 3-2 原图 1/1 和 8 项数据显示故障注入检查均通过，GitHub CI 通过。

新增 15 项回归覆盖半秒截图调度、新组冷却、过期成功/失败回调、同组复用、独立确认帧、退出以及连续刷新后只发布最新结果。原先的延迟问题已用失败测试复现后修正。

留存真实 4K 图片的 16 秒连续回放中，25 次模拟画面检查仅执行 1 次真实 OCR，首个结果用时约 1.22 秒。回放使用冻结统计与模拟取图，未进行游戏截图、在线延迟或游戏 FPS 测量。0.5 秒是检查调度间隔，不是端到端排名显示时限；线程忙碌时会跳过重复任务。

每版发布前，重新构建实际 ZIP，在仓库外中文及空格路径运行包内 EXE 的离线与联网诊断，并验证逐文件哈希、356 组数据显示、留存截图 OCR、模型、WebEngine、DataJ HTTPS 与英雄头像。附件为 ZIP 与 `.zip.sha256`，本机验证结果保存在同名 `.validation.json`。只有 CI、包验证和附件上传均成功后才公开发布。

本轮按既有要求不启动 MuMu；构建机隔离验证不等于另一台物理电脑或实战验证。此前的定阵海克斯补查与装备检索验证记录见 [v0.2.8](v0.2.8.md) 与 [v0.2.7](v0.2.7.md)。
