# 目录管理与保留规则

整理日期：2026-10-09。源码和已有样本路径保持稳定，避免破坏启动、打包与原图回放。

| 位置 | 内容与管理方式 |
| --- | --- |
| 根目录 | 启动入口、项目说明、更新记录和Git配置 |
| `outputs/companion/` | 助手源码、资源与测试；名称虽为outputs，不能当作生成物清理 |
| `outputs/mumu-p0-probe/` | 共用窗口、截图、OCR模块及测试，属于运行依赖 |
| `outputs/` 其余文档 | 早期设计与验证证据；保留原路径，由文档索引统一导航 |
| `docs/` | 当前设计、研究、验证和版本说明，新文档放入对应子目录 |
| `tools/` | 可复用的开发与验证工具；一次性实验不进入此目录 |
| `packaging/` | 构建、依赖和包验证工具 |
| `dist/` | 最新及上一版发行包；旧正式版归入 `archive/releases/<版本>/`，旧候选归入 `archive/candidates/<版本>/` |
| `work/p0-runtime/` | 本机Python环境及OCR模型，不自动清理 |
| `work/companion/` | 当前设置、缓存、日志及问题原图，不自动清理 |
| `work/` 其余目录 | 实验、实战样本与原始验证记录，以本机README分类索引；已引用目录不随意移动 |
| `work/package-build/` | 可重建的打包目录；保留验证与来源记录，生成的build/dist可清理 |
| `work/housekeeping/` | 整理清单、归档映射及删除文件哈希，仅保留本机 |

## 本次处理

- 50个旧包及附属文件按版本归档，每个文件移动前后SHA-256一致。
- 删除3195个可再生成或明确废弃文件，共1,147,771,601字节（约1.07 GiB）。
- 删除范围：打包生成的build/dist、源码和工具的Python字节码缓存，以及两份已标记aborted/rejected的旧候选ZIP。废弃候选的验证记录和删除前哈希仍保留。
- `migration-copy.log` 收入本机整理记录；正式发行ZIP未删除。
- 当前源码助手保持运行；已有未跟踪研究文件保持原状。本次不提交或推送。

详细清单：`work/housekeeping/2026-10-09/` 下的 `moves.json`、`deleted-files.json`、`summary.json`。删除清单用于审计，不是被删文件的备份。

## 后续规则

1. 新的报告按用途进入 `docs/design`、`docs/research`、`docs/testing` 或 `docs/releases`。
2. 新实验使用 `work/experiments/<日期>-<主题>/`，原图和人工标注作为证据保留；旧路径维持兼容。
3. 发行包必须连同校验值和验证报告归档，不修改冻结ZIP；构建工具也检查归档内同名包，防止复用旧版本号。
4. 清理build/dist后下次完整构建。不要把运行环境、模型、黄金样本、用户原图或运行中的目录纳入批量删除。
5. `work/`、`dist/` 继续由Git忽略；本机索引在其他机器上可能不存在。
