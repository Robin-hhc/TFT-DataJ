# 后缀海克斯能否通过中文前缀、品质和阶段识别

2026-10-21。范围是当前 `setId=18` 的 DataJ 目录及本机已批准原图；这是一轮可行性调查，没有修改线上识别、运行实例或批准答案。详细命令及验证边界见[本轮记录](../development-records/2026-10-21-suffix-feasibility.md)。

## 结论

用户提出的办法对当前目录的 **19 个纯罗马数字家族、34 条成员全部成立**：准确中文前缀加上真实品质，就能唯一确定 ID，阶段不参与也能完成。13 个家族有多个版本，靠品质区分；另 6 个家族当前只有一个版本。这是完整目录的唯一性证明，尚不是自动颜色识别的准确率或上线验收。

把 `+`、`++` 一起纳入后，总计 **48 个家族、100 条成员**，其中 72 条名字实际带后缀、28 条为同家族无后缀版本。纯加号 28 个家族中有 26 个仍存在同品质候选；混合家族只有秘法帮派，其彩色 II、II+、II++ 也需继续区分。全量清单在下表及 [CSV](suffix-identity-catalog-20261021.csv)，没有用少数成功样本代替全量统计。

阶段方面，27 个同品质冲突家族中，21 个在当前 18.4 统计快照内所有候选均有正向阶段记录且互不重叠，支持“后缀随获得阶段变化”的思路；另 3 个部分缺失、3 个全部缺失。目前没有得到这 27 组当前游戏的完整生成规则，因此这 21 组只能称统计支持，不能直接作为排除其他候选的硬规则。[逐组阶段证据](../../work/suffix-feasibility-20261021/stage-agent/stage-evidence.json)

## 数据范围与独立检查

1. 本轮直接请求 [DataJ gamedata](https://www.dataj.cc/api/web/gamedata?setId=18)，HTTP 200，当前原始目录 268 行。对照源码只读 SQLite、10-18 原始响应以及最新已批准病例冻结的 263 行目录，全部 100 条家族成员的字段逐值一致。263 与 268 的差异来自其他同名实体的既有目录投影，本清单没有因统计缺失删除候选；五个差异不在这 100 条内。[目录四源核对](../../work/suffix-feasibility-20261021/catalog-agent/catalog-family-audit.json)、[既有投影边界](../../outputs/companion/hex_catalog.py#L16)
2. 分类只解析末尾 I／II／III 和 +／++，以 NFKC 统一 Unicode 形态、忽略空白，保留前缀的标点，不使用中文模糊匹配。原始标题、ID、品质保留，不从后缀序号或 ID 数字推断品质。[库存算法与逐行结果](../../work/suffix-feasibility-20261021/catalog-agent/all-family-table.json)
3. 品质读取目录 `level=1/2/3`。例如投资策略 I、珠光莲花 I、终身黄铜 I 都是金色，其 II 为彩色；值得等待 II 也是彩色。这些反例不妨碍方案，因为方案读取真实品质再查目录，不把 I 固定解释成银色。[全量原始名称和品质](suffix-identity-catalog-20261021.csv)
4. 根代理独立重算家族及全部纯罗马成员查询：34/34 在假定前缀、品质正确时唯一返回原 ID；11 项边界检查通过，包含未知品质、错误中文、金色 I、同品质加号歧义。这是信息充分性实验，不是把模拟正确输入计作 OCR 测试。[独立实验脚本](../../work/suffix-feasibility-20261021/audit_lookup.py)、[结果](../../work/suffix-feasibility-20261021/lookup-upper-bound.json)

## 原图上的可用信号

品质色位于标题上方的大图标，银色为灰蓝、金色为黄色、彩色为多色渐变；统一绿色底及金色藤边不能用来判断。本轮实际查看 46 份批准原图的 5 页原像素联系图，共 138 个固定位置：人工标记银 50、金 56、彩 22、没有可用图标 10。先记录像素颜色，再与独立批准 ID 对应的冻结目录品质交叉核对；105 个已有批准 ID 的槽位全部一致，0 个不一致。另外 33 个无批准 ID 或非选牌位置不计作颜色正确。这是人工观察，尚未实现或验收自动品质分类。[手工像素观察及哈希](../../work/suffix-feasibility-20261021/root-manual-colors.json)、[标签与交叉检查脚本](../../work/suffix-feasibility-20261021/check_manual_colors.py)

拥抱 I、嘀个痛快 I 的银色图标清晰；暗色拥抱 II 的标题整体变暗，但金色图标仍可辨；秘法帮派 II++ 的图标为彩色渐变；终身黄铜 I 的图标确实是金色。这些信号不依赖先读对后缀。星界赐福 III 和一张假人化原图则有阵容提示浮层遮挡图标上半部，下部仍可见品质色，人工可辨不代表程序能稳定分类。10 个无可用图标位置及动画、变暗、遮挡都须加入自动读取的拒识/置信度验证，不能仅因位置里存在一点黄色或彩色就认定品质。[逐位置观察](../../work/suffix-feasibility-20261021/root-manual-colors.json)

## 实施建议与尚缺验收

这些是工程建议，不是本轮已经上线的行为：

1. 为本次核准目录建立版本绑定的家族索引，前缀需两次可信、不同像素的字面共识。罗马数字不再是唯一证据通道；原有完整标题仍保留，可信完整后缀和品质发生冲突时不能悄悄覆盖。
2. 增加独立的图标品质读取，避开绿底、金边及动画未展开的画面。先对 19 个纯罗马家族启用“前缀＋品质”的交叉验证及补全，未知品质、目录歧义或目录更新失配继续拒绝；准确前缀和准确品质仍需各自的置信度与拒识保护。
3. 对加号家族建立带来源、版本与审核记录的生成阶段规则。优先核准秘法帮派 II／II+／II++ 等常见家族；尚未核准的使用原有完整标题或可独立区分的描述，不依据统计缺项排除实体。
4. 原图回归除后缀漏读正例，还需品质读错/不确定、相同品质＋相同阶段候选、阶段缺失、中文缺字/错字、动画、目录变化和完整标题冲突等负例。实际代码改动后按统一流程跑私有回放及发布检查，本轮的目录实验不能替代这些门槛。

本轮没有改动识别代码、回归登记或批准答案，没有重新打包；自动颜色分类、真实游戏连续帧、现场 FPS、EXE 与其他电脑均未由本调查验收。源码和原始证据保护结果见[验收记录](../development-records/2026-10-21-suffix-feasibility.md)。
